# Agent API and LLM Architecture Specification

**Date:** 2026-08-30  
**Scope:** Architecture and parity contract for the Go agent API, configuration model, immutable LLM DTOs, and OpenAI-compatible client in `zenbot`. This document is an implementation specification, not an implementation. It explicitly excludes routing, tools beyond wire-level tool-call data, execution, turns, persistence, moderation, listeners, and commands.

## Required parity

**API shape.** Preserve field meaning, wire names, enum spellings, nullable fields, and defaults. `InvocationMode` must serialize using the established uppercase values; unknown values must fail validation rather than silently becoming a valid mode. Optional identity/context/result data must remain distinguishable from an explicitly empty string or zero. JSON omission (`omitempty` or equivalent) is permitted only where Saturn omits absent values; it must not erase a semantically present null. Constructors or validators must reject structurally invalid invocations while allowing valid empty collections where Saturn does.

**Configuration.** Establish one documented precedence chain: explicit/runtime values override environment-derived values, which override file/database values, which override defaults; `APIKeyEnv` names the environment variable and is not itself the secret. Normalize endpoint joining so a configured base URL and `/v1/chat/completions` cannot produce duplicate or missing slashes. Validate required fields (`Enabled` may govern whether other fields are required), positive durations and token/step/tool limits, nonnegative retry counts and delay, supported temperature range, and syntactically valid URLs. Enforce Saturn-equivalent upper bounds for `MaxTokens`, `MaxSteps`, and `MaxTools` before constructing a client. Invalid configuration must return actionable errors naming the field; no silent clamping. `TimeoutMillis` converts to a context/request timeout without overflow and preserves cancellation semantics.

**Immutable LLM DTOs and JSON.** DTOs must be value-oriented and immutable after construction: callers cannot mutate message content, tool-call slices, or response metadata through retained aliases. Use defensive copies at boundaries and expose read-only behavior or copied slices. Define exact JSON tags for role, content, name, tool calls, tool-call IDs, function names, and arguments. Preserve nullable content: assistant tool-call messages may have JSON `null` content, while ordinary text content remains a string. Marshal requests with only supported fields; unmarshal responses without losing finish reason, usage, tool calls, or provider error payloads. Tool arguments remain raw JSON/string data rather than being eagerly interpreted.

**OpenAI-compatible HTTP behavior.** Build the request as `POST {normalized endpoint}/v1/chat/completions` with `Content-Type: application/json`, `Authorization: Bearer <token>`, model, messages, optional sampling/token settings, and tool definitions/calls according to the DTO contract. Use an injected `http.Client` and context-bound requests. Retry only transient transport failures and retryable HTTP statuses (for example 408, 429, and 5xx), bounded by `MaxRetries`; do not retry malformed requests, authentication failures, or other permanent 4xx responses. Respect `Retry-After` when valid, otherwise use `RetryDelay`; cancellation must interrupt both backoff and in-flight I/O and return `context.Canceled`/`context.DeadlineExceeded` observably. Return typed errors carrying status, provider code/message when available, and safe response snippets without leaking tokens. Decode successful JSON strictly enough to detect malformed or incomplete responses, while retaining useful provider diagnostics.

## Target signatures and file map

Keep the public seam small. In `internal/agent/api/api.go`, retain `type InvocationMode string`, the four constants, and explicit construction/validation functions such as `ValidateInvocation(Invocation) error`. In `internal/config/agent_config.go`, provide `func (c AgentConfig) Validate() error` and `func (c AgentConfig) Resolve(r ValueReader) (ResolvedAgentConfig, error)`; keep secret lookup separate from config serialization. In `internal/agent/llm/client.go`, define `type Client interface { Complete(context.Context, LlmRequest) (LlmResponse, error) }`, constructors that defensively copy DTO data, and stable marshal/unmarshal helpers where needed. In `internal/agent/llm/openai/client.go`, expose `func New(cfg Config, httpClient *http.Client) (*Client, error)` and `func (c *Client) Complete(context.Context, llm.LlmRequest) (llm.LlmResponse, error)`. Keep endpoint normalization, retry classification, backoff, and error decoding in focused private helpers or adjacent files; do not spread provider policy into API contracts.

## Focused verification

Add table-driven tests for every invocation mode, unknown enum, nullable versus omitted fields, defensive-copy behavior, and constructor rejection. Test configuration precedence, environment lookup, URL normalization, each invalid limit, defaults, and timeout conversion. For OpenAI, use `httptest.Server` to assert method/path/headers/body, tool-call and tool-result JSON, bearer auth, malformed responses, status-to-error mapping, retry counts, `Retry-After`, and no retry on permanent 4xx. Use contexts with cancellation during backoff and request execution; assert prompt cancellation and error identity. Include race-enabled tests or targeted alias checks for immutability. Run the focused package tests plus `go test -race ./internal/agent/... ./internal/config/...` before integration.

## Risks, assumptions, and complexity

Risks include subtle Saturn-versus-Go JSON null semantics, accidental slice/map aliasing, endpoint double-prefixing, retry storms, and leaking provider responses. The specification assumes the existing Go scaffold names are stable and that Saturn tests define defaults and numeric limits where this document intentionally avoids inventing values. Any discrepancy discovered while porting must be recorded as a compatibility decision, not silently changed. Expected complexity is **medium**: roughly three cohesive implementation areas (API/config/LLM transport), with most effort in contract tests and error/cancellation edge cases rather than algorithms. HTTP behavior remains O(number of attempts × payload size); memory is O(payload size) per request/response.

## Explicit exclusions

This work does **not** design or implement routing, tool selection or tool execution, agent execution loops, turns, persistence, moderation policy, event/listener integration, or CLI/HTTP commands. Tool calls are represented only as immutable LLM wire data so the client can preserve provider parity. Those excluded concerns require separate specifications and must consume these contracts rather than expanding this boundary.

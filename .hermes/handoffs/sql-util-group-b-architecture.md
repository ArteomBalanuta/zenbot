## Required engineering and acceptance gates

1. **TDD:** Write contract tests first (RED), obtain the explicit interface decision, implement the smallest approved mapping (GREEN), then refactor without changing SQL/result semantics.
2. **Evidence gate:** Transcribe exact Saturn SQL from collected/source evidence before implementation. Until then, every row above remains `SQL transcription required`; no guessed SQL is acceptable.
3. **Independent QA:** A reviewer who did not implement the change verifies the Saturn-to-target mapping, authorization boundaries, projections, ordering, visibility filters, limits, and real-H2 assertions.
4. **Real-H2 gate:** Tests must run against H2, not mocks; cover positive, empty, boundary, collision/scope, authorization, ordering/tie, and atomicity cases relevant to each approved contract.
5. **No adaptation gate:** No positional column swapping, implicit `PUBLIC` filtering, model enrichment, tie-break insertion, or scope broadening/narrowing unless explicitly adopted in the target contract and tested.
6. **Acceptance:** Contract decision recorded; exact SQL evidenced; existing repository/H2 tests pass; new real-H2 tests pass; independent QA signs off; diff remains limited to authorized existing H2/repository paths.
